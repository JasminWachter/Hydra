# MulVAL rule knowledge base

This directory holds the rules that turn scanner findings into attack graphs. Rule reasoning is
**two-layered**: Semgrep rules localize evidence into input predicates, and the MulVAL interaction
rules chain those predicates into an attack graph.

```
source code ──Semgrep rules──▶ input predicates ──MulVAL interaction rules──▶ attack graph
(semgrep_rules/*.yaml)         (taint_flow, sink_evidence,   (kb/web_security_rules.P)   (paths.json)
                                detected_vuln, web_service…)
```

## Files

| File | Role |
|------|------|
| `web_security_rules.P` | **Active KB.** 124 interaction rules across a 12-stage web kill chain. Loaded by default (`mulval_executor.resolve_rules_file`). |
| `full_interaction_rules.P` | Full MITRE ATT&CK rule set (533 techniques, auto-generated). Override with `--rules kb/full_interaction_rules.P`. Not used by the web pipeline. |
| `full_post_exploit_rules.P` | Curated MITRE post-exploitation subset (generated by `tools/curate_post_exploit.py`). **Future work — NOT combined at runtime** (see “Rule loading” below). |
| `tools/curate_post_exploit.py` | Generator for `full_post_exploit_rules.P`. |

The Semgrep evidence rules live one level up in [`../semgrep_rules/`](../semgrep_rules) and are
documented in the “Evidence layer” section below.

## Input predicate vocabulary

Facts the interaction rules consume, grouped by producer. Full producer details are in
[`../parsers/`](../parsers).

| Group | Predicates | Producer |
|-------|-----------|----------|
| Network | `attacker_at/1` `host/1` `connects/3` `exposed/2` `service/5` `role/2` | nmap, app-features |
| Web context | `web_service/3` `has_user_input/3` `has_login_form/2` `has_file_upload/2` `has_api_endpoint/4` `has_cookie_auth/2` `uses_database/3` `web_framework/3` `dangerous_http_methods/2` `no_auth_required/2` `auth_service/2` `has_data/2` | nmap, app-features |

| Non-exploitable | `detected_weakness(Host,Port,Class,File,Line)` | Semgrep (unclassified findings) |

## Evidence layer (`../semgrep_rules/`)

49 rules across PHP (`web_taint.yaml`), JS/TS (`web_taint_js.yaml`), Python (`web_taint_python.yaml`)
and Java (`web_taint_java.yaml`), plus the stock `p/owasp-top-ten` pack as a fallback. Findings are
turned into predicates by `parsers/semgrep_parser_strategy.py`.

**Tier 1 — proven dataflow (`mode: taint`).** A source→sink flow the engine can prove. Emits
`taint_flow(...)` **and** `detected_vuln(...)`; confirmed at high confidence (~0.9). Classes: `sqli`,
`cmdi`, `ssrf`, `xss`, `path_traversal`, `xxe`, `ssti`, `deserialization`, `auth_bypass` (PHP
loose-hash / Python unverified-JWT), `prototype_pollution` (JS structural merge).

**Tier 2 — heuristic sink shapes (`evidence_tier: heuristic`).** A dangerous sink called with a
dynamically-built argument (f-string / concat / template literal into `execute`, `system`, `include`,
`render_template_string`, `unserialize`, `pickle.loads`, …). These fire **across function boundaries**
that the free Semgrep engine can’t taint-track (the main coverage gap for real CTF bugs). Emits **only**
`sink_evidence(...)` — never `taint_flow`/`detected_vuln` — so it cannot borrow tier-1 confidence.
Classes: `sqli`, `cmdi`, `path_traversal`, `ssti`, `deserialization` (subset per language).

**Markers & hygiene.** `flag-in-cookie` → `flag_location`, `localhost-only-gate` → `access_gate`;
any real finding that doesn’t map to a taint class becomes `detected_weakness` (recon annotation only,
never chains to compromise).

## Interaction rules (`web_security_rules.P`)

124 rules over a 12-stage kill chain (MITRE technique IDs are in each `rule_desc`). Predicate flow:

```
scanner facts → recon_complete → *_surface → *_confirmed → initial_access → exec_achieved
             → priv_escalated → cred_obtained → data_exfiltrated → lateral_access → compromise → execCode
```

| Stage | Head predicate(s) | Notes |
|-------|-------------------|-------|
| 1  Reconnaissance | `recon_complete/2` | Always-present orientation floor (host_reachable, service_enum, web_fingerprint, weakness_identified, …). Never chains to compromise. |
| 1b Information disclosure | `info_disclosure_confirmed/2`, `compromise/2` | Read-only objectives: `info_disclosure`, `auth_bypass`, `xxe`, `prototype_pollution` reach `compromise` without code execution. |
| 2  Attack surface | `*_surface/2` | Context-aware class detection from web context (sqli, cmdi, ssrf, xss, path_traversal, auth_bypass, idor, upload_vuln, deserialization, nosql_injection, xxe, ssti, prototype_pollution, cors). Recon hints only — cannot self-confirm. |
| 3  Confirmation (tier 1) | `*_confirmed/2` | From `detected_vuln` **or** `taint_flow` (localized, ~0.9). |
| 3b Confirmation (tier 2) | `*_confirmed/2` | From `sink_evidence(...)` **gated on `has_user_input`** (~0.5). Localized; ranks strictly below tier 1. |
| 4  Initial access | `initial_access/3` | T1190 / T1078 / T1185. Evidence-backed and heuristic-fallback variants. |
| 5  Execution | `exec_achieved/2` | Only execution-capable classes: cmdi, sqli(+DB), upload_rce, ssti, deserialization, known_cve. |
| 6  Privilege escalation | `priv_escalated/3` | T1068 / T1548. |
| 7  Credential access | `cred_obtained/3` | T1003 / T1552 (sqli/nosqli/path-traversal/xss-session/ssrf-metadata). |
| 8  Data exfiltration | `data_exfiltrated/3` | T1005 / T1530. |
| 9  Lateral movement | `lateral_access/2` | T1021 / T1078. |
| 10 Compromise | `compromise/2` | All routes converge (root / web_user / user / data_breach / flag_*). |
| 11 MITRE bridge | `execCode/2` | Maps every `compromise`/`exec_achieved` to the standard `execCode` goal the graph renderer needs. |
| 12 Flag localization | `compromise(_,flag_*)` | Attaches the concrete `flag_location`/`access_gate` to the terminal. |

### Goal predicates

`generate_attack_goals` queries three terminals so a graph is **always** produced:
`execCode(Host,_)`, `compromise(Host,_)`, and `recon_complete(Host,_)`. When no exploitation evidence
exists, only the reconnaissance subtree renders (never a fabricated exploit). `paths.json` emits one
path per distinct route to each terminal, ranked by confidence (proven tier-1 routes above heuristic
tier-2; recon last) — see `trace_processor.parse_trace_to_json`.

## Rule loading

`mulval_executor.resolve_rules_file` uses **`web_security_rules.P` alone** by default. It already spans
the full kill chain and its recon tier guarantees a non-empty graph.

`full_post_exploit_rules.P` is **intentionally not combined**: appending it breaks MulVAL derivation
(no-evidence targets stop deriving `recon_complete`, and `execCode` becomes spuriously derivable with
an empty trace) because it carries ICS-grounded intermediate predicates and duplicate tabling
directives. Re-integrating a fixed post-exploitation layer is tracked as future work.

## Adding coverage

- **New bug idiom, same class:** add a Semgrep rule in `../semgrep_rules/<lang>.yaml`. Use `mode: taint`
  for a provable flow (tier 1) or a `patterns` sink-shape rule with `evidence_tier: heuristic` (tier 2).
  Set `metadata.vuln_class` to an existing class and the existing interaction rules light up
  automatically.
- **New vulnerability class:** add `*_surface` / `*_confirmed` derived predicates (+ tabling) and a
  chain to `initial_access`/`exec_achieved` or a read-only `compromise` in `web_security_rules.P`
  (mirror `prototype_pollution`), and ensure the class appears in `benchmarking/.../metrics.py`
  `VULNERABILITY_SIGNATURES`.

Validate Semgrep rules with the pinned local CLI: `semgrep scan --validate --config ../semgrep_rules
<src>`.
